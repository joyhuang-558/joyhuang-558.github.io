The Trap

Self-evolution overfits to its own criteria.

Symptom

Proposer ↔ solver reinforce each other's errors.

Mechanism · cross-fit

Samples generated on A are scored by a solver trained only on B.

Conclusion

The accept/reject signal must come from data the evolver has never seen.

The deciding signal must come from unseen data.
Source · [5] CrossFit / False Frontiers (arXiv 2609.39102)
the trap
The Playbook

The evolver follows a six-step playbook.

1Diagnose by failure mode
2Mechanisms > exhortation (for small models)
3One change at a time
4Self-verify before accepting
5Holdout decides
6Intervene only on diagnosed problems
Diagnosis-driven, targeted fixes.
playbook
The Split

Keep a set the evolver never touches.

A  learning set

Evolver learns and self-tests here. run_candidate runs on A only.

B  held-out

Decides accept / reject. The evolver can neither see nor run it.

C  final

Untouched. Plays no part in selection; tested once after freezing.

The evolver can't see the data that judges it.
the split
The Loop

Propose on A, decide on B.

Propose

The evolver is given run_candidate.

Test

Candidates are tested on held-out B.

Decide

The B score decides accept / reject.

CrossFit's held-out reward, put into practice.
